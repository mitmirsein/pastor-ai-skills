# 🧷 표준 훅 (Standard Hooks) — 단일 정의

> 모든 전문 스킬의 결과 저장·메모리 갱신·환경 폴백 **절차**는 이 파일이 단일 진실 공급원입니다 (v2.8 P3-10).
> 각 스킬 하단의 `### 🧷 표준 훅` 블록은 *파라미터*만 선언하고, 절차는 본 파일을 따릅니다.
> 절차를 고칠 일이 생기면 **이 파일만** 고치십시오. 스킬마다 복붙된 절차는 표류(drift)합니다.

---

## §1. 모드 판별 (AGENT / CHAT) — 침묵 실패 금지

스킬 실행 시작 시(또는 Concierge 부트 시) 환경을 1회 판별합니다.

- **읽기 능력**: 지침·상류 파일을 실제로 열 수 있는지 확인한다. 읽을 수 있으면 자동 참조를 사용한다.
- **쓰기 능력**: 대상 경로의 쓰기 권한과 도구 가용성을 별도로 확인한다. 읽기 성공은 쓰기 성공의 증거가 아니다.
- **자료 가용성**: 본문·원고·원어·주석 각각 제공 범위와 출처를 확인한다. 환경 모드와 자료 완전성을 혼동하지 않는다.
- **AGENT 모드**: 파일 읽기가 가능한 환경. 쓰기도 가능할 때만 §2~§3을 실행한다. 읽기 전용이면 자동 참조 후 §5로 결과를 건넨다.
- **CHAT 모드**: 파일 접근이 없는 환경. 대화에 실제 제공된 지침·자료로 실행하고 §5를 따른다. 저장소 전체를 읽었다고 가정하지 않는다.

실제 쓰기 실패는 CHAT으로 이름을 바꿔 숨기지 않고 §2.7의 부분 성공으로 보고한다. 저장된 경로와 읽기 재확인이 없으면 “저장되었습니다”라고 말하지 않는다.

### §1.1 입력 재사용·중단·재개

요청과 대화에 이미 있는 본문·원고·대상·분량·제외 범위·위임을 전문 스킬에 원문 그대로 전달한다. 필수 누락만 한 번 묻는다. 이번 명시 지시는 저장된 기본값보다 우선하며 샘플 설정은 확정값이 아니다. 묵상·씨앗을 연구나 원고 검토의 필수 선행 단계로 강제하지 않는다.

“그만/여기까지 저장/나중에 이어서”면 질문과 CTA를 멈추고 현재까지의 사용자 원문과 미결 항목만 보존한다. 파일 메타 `work_status: paused`와 `resume_at`(미결 절차, 개인정보 제외)을 남기며 임의 결론을 짓지 않는다. “앞의 선택 취소”는 해당 선택만 미확정으로 되돌리고 원문·저장 이력을 삭제하지 않는다. 재개 시 지정 파일 또는 최근 실제 파일을 읽고 미결 지점부터 이어간다. 대상이 여러 개로 모호할 때만 하나를 확인한다. 제목·디자인 등 가역적 선택을 위임받았으면 추천 기본값으로 초안을 만들고 대안은 선택 사항으로 둔다. 의미 확정·민감 내용 포함은 위임을 추정하지 않는다.

## §2. 결과 저장 (Persistence)

스킬의 `save` 파라미터에 따라 저장 위치를 결정합니다.

| save | 경로 | 비고 |
|---|---|---|
| `sermons-lineage` | `outputs/sermons/{passage_id}/v{NN}_{skill}_{date}.md` | 본문 중심 lineage |
| `series` | `outputs/series/{series_id}/` | 시리즈 기획 |
| `dated` | `outputs/{date}/{category}/{skill}_{topic}.md` | 비-본문 작업물 |
| `devotional-fallback` | 본문 식별 시 lineage, 아니면 `outputs/devotionals/{topic-slug}/` | 묵상 폴백 |
| `qt-log` | `outputs/devotionals/{passage_id 또는 topic-slug}/v{NN}_{skill}_{date}.md` | 매일 큐티 로그 — 본문이 식별돼도 설교 lineage로 **조기 승격하지 않고** devotionals/에 누적(발아 코퍼스). 설교 lineage로의 승격은 나중에 `qt-germinate-seed`(`sermons-lineage`)가 담당. **인덱스 누적**: 저장 시 `outputs/devotionals/_index.md`에 한 줄 append — `- {date} · {passage_id 또는 topic-slug} · {키워드 1~2개} · {파일 경로}` (없으면 생성; 발아 스캔·주간 브리핑의 1차 스캔 소스 — 코퍼스가 커져도 전수 집계 가능) |

공통 절차:
1. **본문 식별**: `passage_id` = `{book-slug}-{ch}-{vstart}-{vend}` (예: 마가 5:25-34 → `mark-5-25-34`). 장 전체를 아우르는 묵상이라 절 범위가 불명확하면 `{book-slug}-{ch}`로 축약할 수 있다(예: `leviticus-4`·`amos-1` — 발아 코퍼스의 장 단위 큐티 관례). 모호하면 사용자에게 확인, 본문이 없으면 `topic-{slug}` 폴백.
2. **버전 번호**: 대상 폴더를 스캔하여 다음 `v{NN}` 결정. 동일 저장의 재시도는 §2.7의 기존 경로를 재사용하며 새 버전을 만들지 않는다.
3. **YAML 메타데이터**: `date`, `skill`, `category`, `passage_id`(해당 시), `version`, `topic`, `stage` + 스킬별 `extra` 필드.
   - *(v2.15, 선택)* `seed_refs`: 뿌리 큐티/씨앗의 **레포 상대 경로 리스트** (절대 경로 금지; 외부 자료는 아래 출처 규약). 기록 주체 — `qt-germinate-seed`(수집한 큐티 전체 자동) · `qt-to-column`(사용한 큐티/씨앗). 이후 lineage 단계(brainstorming·outline 등)는 AGENT 모드에서 같은 lineage 폴더에 씨앗 파일이 있으면 그 `seed_refs`와 `source_refs`를 상속하고, 붙여넣기만 받은 CHAT 모드에서는 생략한다(모르는 출처를 지어내지 않는다). 소비처 — 씨앗 거울(`sermon-outline-codraft` 4.5단계)·`sermon_audit` Claim Ledger ⑤(일화 대조)·가계도(v2.17 예정).
   - 외부 큐티는 `source_refs`에 `{source_id, relative_path, sha256}`를 기록한다. `source_id`는 `qt-source-` + 설정된 외부 루트 정규 절대 경로의 SHA-256 앞 16자리로 만든 로컬 별칭이며 절대 경로·사용자 홈 이름은 산출물에 노출하지 않는다. `relative_path`는 그 루트 안의 경로만 허용한다. 별칭→실제 루트는 로컬 `qt_source_path` 각 경로의 같은 해시를 대조해 해석하고, 접근 불가면 검증 불가로 남긴다. 외부 파일을 레포 안에 있는 것처럼 `seed_refs`에 만들지 않는다.
4. **Manifest 갱신**: `_manifest.md`를 **읽고-병합-쓰기** (없으면 신규 생성). 라인 형식: `- v{NN} {skill} ({date}) — {스킬별 manifest_line} · {레포 상대 파일 경로}`. 구 행은 같은 폴더의 버전·스킬·날짜로 실제 파일을 하나로 식별할 때만 경로를 보완하며, 모호한 행은 임의 병합하지 않는다.
5. **칼럼 인덱스 (v2.17):** 칼럼 스킬(`sermon-to-column`·`qt-to-column`)의 저장 시 `outputs/columns/_index.md`에 한 줄 append — `- {date} · {주제} · {문체} · {지면 또는 "-"} · {파일 경로}` (없으면 생성). 저장 위치 자체는 불변(lineage)이며 인덱스만 추가 — `weekly-briefing`·`recall`(5차·가계도)의 칼럼 축 소스.
6. **설교 인덱스 (v2.18):** `save: sermons-lineage` 저장마다 `outputs/sermons/_index.md`에 한 줄 append — `- {date} · {passage_id} · v{NN} {skill} · {stage} · {키워드 1~2개} · {파일 경로}` (없으면 생성). devotionals `_index.md`(qt-log)·columns `_index.md`(§2.5)와 대칭 — 설교 축만 인덱스가 없어 코퍼스가 커지면 `recall`·`weekly-briefing`이 전 `_manifest.md`를 전수 스캔해야 했던 공백을 메운다. 소비처: `recall`(주제·시기 질의 1차 소스)·`weekly-briefing`(설교 축 집계)·가계도. 새 파일 저장 없이 stage만 바뀐 경우에는 append하지 않는다(라인 = 파일 1개).

### §2.7 부분 저장·재시도·복구

저장은 산출물 → manifest → 각 인덱스 → journal 순서다. 원자적 전체 성공을 가정하지 않는다.

1. 실행마다 `operation_id`를 하나 정하고 대상 버전·경로를 예약한다. 재시도는 같은 ID와 경로를 쓴다. 각 대상의 변경 전 해시(미존재는 null), 변경 후 내용, 완료 여부를 `outputs/.operations/{operation_id}.json`에 로컬 기록한다. 원문이 포함될 수 있으므로 외부 전송·커밋하지 않는다.
2. 쓰기 전 최신 파일을 다시 읽어 병합한다. 콘텐츠 산출물은 새 파일만 생성하며 기존 본문을 덮어쓰지 않는다. 실제 게시 확인에 한해 §3.6의 frontmatter 변경을 허용하되 변경 전후 본문 바이트를 대조하고 계획에서는 일반 메타 변경으로 표시한다. 인덱스·manifest 행은 **정규화한 산출물 상대 경로**를 키로 upsert한다. journal의 같은 operation 메모·게시 사건을 중복 추가하지 않는다.
3. 각 파일은 같은 디렉터리 임시 파일에 쓰고 교체한 뒤 읽기 대조한다. 파일별 성공을 기록한다. 후속 갱신 실패 시 이미 저장한 산출물은 보존하고 “결과 저장됨 / 인덱스 갱신 실패”처럼 정확한 단계와 결과 링크를 보고한다. 결과 파일 자체가 실패하면 저장 성공을 말하지 않는다.
4. 재시도는 현재 해시가 변경 후와 같으면 완료로 건너뛰고, 변경 전과 같으면 미완료 쓰기만 재개한다. 둘 다 아니면 다른 편집이 있었으므로 중단하고 최신 내용과 병합안을 만든다. 오래된 journal 전체를 덮어쓰거나 새 v번호로 같은 결과를 복제하지 않는다. 병합으로 계획 내용이 달라지면 새 operation_id와 `supersedes: 이전-ID`를 사용한다. 확인된 완료 artifact는 새 쓰기 목록에서 제외하고 미완·충돌 파일만 최신 해시와 병합 내용으로 복구한다. 이전 영수증은 보존하며 새 영수증 완료와 실제 파일 대조를 함께 확인한다.
5. 인덱스 복구는 해당 루트의 **모든 기존 폴더 안 파일도** 열거하여 frontmatter와 경로에서 재구축한다. 파일 경로별 한 행, 개별 `date`를 사용한다. 잘못된 메타는 오류 목록으로 남기고 날짜를 추정하지 않는다. 원본 산출물은 불변이며 인덱스만 교체한다. 본체 상태는 §3.6의 확인 사건과 journal/manifest를 대조하며 인덱스 최신 stage를 권위로 삼지 않는다.
6. 자동화가 없더라도 위 로그·해시·재개 규칙을 실행한다. 저장 도구가 있으면 `tools/persistence/README.md`의 계획 파일 절차를 사용한다. 도구는 병합·신학 판단을 대신하지 않으며 검토한 파일 변경만 적용한다.

## §3. 메모리 갱신 (Journal Update)

`core/pastor_journal.md`를 **읽고-병합-쓰기**로 갱신합니다. 절대 통째로 덮어쓰지 않습니다.

1. 스킬의 `journal` 파라미터에 따라 `active_sermons` / `active_series` / `active_visitations` 항목을 갱신 또는 추가 (`stage`, `next_step`, `notes` 한 줄). 시리즈 항목을 갱신할 때는 `active_series.last_updated`도 함께 갱신합니다 (정체 감지용).
2. `recent_topics`에 핵심 키워드 1~2개 FIFO 추가 (12개 한도, 중복 제거).
3. `last_updated` 갱신.
4. **PII 정책 엄수** (`pastor_journal.md` §2): 실명 → 직분+이니셜 변환, 연락처·병명 상세·재정 기록 금지. 사용자가 실명을 입력해도 변환 후 저장.
5. `journal: 갱신하지 않음`으로 선언된 스킬(읽기 전용 도구)은 이 단계를 건너뜁니다.
5.5 **큐티 리듬 (v2.20):** `save: qt-log` 스킬(`qt-companion`)의 저장 시 frontmatter `last_qt_date`를 오늘 날짜로 갱신합니다 — **이 필드는 qt-companion만 만집니다**(`pastor_journal.md` §3.8). 날짜만 기록하며 묵상 내용은 journal에 남기지 않습니다.
6. **발행 전이 가드 (§3.6) — 사건과 작업 분리**:
   - `stage`(산출물의 작업 종류)와 journal `stage`/manifest `current_stage`(본체 진행)를 분리한다. 본체의 유효값·순서는 `pastor_journal.md` §3.1.1을 따른다. 완료된 새 핵심 작업만 enum 순서상 현재보다 뒤의 단계로 전진한다. `work_status: paused`인 미완료 작업은 기존 본체 단계와 journal 등재 여부를 유지하고, 최초 미완료 파일의 manifest `current_stage`는 null로 둔다. 재묵상(`qt_kind: secunda`)·회고·리허설·교안·나눔지·파생물·수정 초안은 단계 순서와 관계없이 본체 불변이다.
   - 파생물 생성은 `publication_status: draft`. 파일의 기존 `published_*` 표기는 작업 종류일 뿐 게시 증거가 아니다. 선포일이 있어도 초안 생성만으로 `published`가 되지 않는다. 이미 있는 항목의 `notes`에 `[파생 초안: {포맷}]`만 기록하고 미등재 본문을 임의로 등재하지 않는다.
   - **실제 선포 확인**: 사용자가 대상 원고와 날짜를 알려준 경우에만 `preached_on`을 기록하고 `preached`로 전진한다. 이미 `published`이면 유지한다.
   - **실제 게시 확인**: 사용자가 실제 게시한 대상 **파일·버전·게시일**을 확인하면 해당 lineage `_manifest.md`의 `publication_events`에 `{artifact_path, version, published_on}`을 기록한다. 동일 세 값은 한 사건으로 병합한다. 게시일이 그 파일의 작성일보다 이르면 과거 원문의 소급 등록인지 날짜 착오인지 필요한 한 번의 확인을 받고, 해소 전에는 사건 전이를 보류한다. 해당 파일의 frontmatter만 `publication_status: published`로 표시하며(본문 바이트는 보존) 후속 버전은 다시 draft다. 외부 게시 실행 자체는 이 기록 절차가 승인하지 않는다.
   - 본체 `published` 전이는 확인된 게시 사건과 `preached_on`이 모두 있을 때만 가능하다. 선포 전 게시 사건은 파일 기록만 남기며, 이후 선포 확인 시 두 증거를 대조한다. `published`는 적어도 한 산출물의 실제 게시를 뜻하며 모든 버전의 게시를 뜻하지 않는다.
   - 기존 기록을 추정으로 재분류하지 않는다. 기존 `published`에 사건 근거가 없으면 조회에서 “과거 기록, 게시 대상 미확인”으로 제한을 표시하고 사용자 확인 전 변경하지 않는다. journal·manifest는 같은 사건으로 병합하며 충돌 시 자동 덮어쓰기 대신 §2.7 복구로 넘긴다.

## §4. 완료 브리핑

사용자에게 결과 링크와 필요한 수정, 다음 행동 **최대 1개**만 짧게 보고한다. 종료·기록만 요청이면 다음 행동을 생략한다. manifest·인덱스·journal 상세는 오류 또는 요청 시만 펼친다. 배포용 본문에는 YAML·해시·제작 메모를 섞지 않고 별도 저장용 기록에 둔다.

## §5. CHAT 모드 폴백 — "저장 대신 건네드립니다"

파일을 쓸 수 없는 환경에서는 §2~§3 대신:

1. 결과물 머리에 §2의 YAML 메타데이터를 붙인 **저장용 완성 블록**을 코드 블록으로 출력하고, 안내합니다:
   > 📋 이 환경에서는 자동 저장이 불가능합니다. 아래 블록을 복사해 `outputs/{권장 경로}`에 직접 저장하십시오.
   - `{권장 경로}`는 이번 날짜·작업으로 계산한 실제 상대 파일 경로로 치환합니다. “권장 감사 경로”처럼 위치를 생략하지 않습니다.
   - 블록에는 `---`로 감싼 YAML **뒤에 결과 본문 전체**가 있어야 합니다. 메타데이터만, 요약만, “위 본문 참조”는 완성 블록이 아닙니다. 중복 출력을 줄이려면 본문은 이 블록에서 한 번만 제공하고, 배포용 본문과 제작 메모를 내부 제목으로 분리합니다. 분량 한계면 명시적으로 나누어 이어 주며 완성 전에는 완료라고 하지 않습니다.
2. journal 갱신분은 **"journal에 추가할 항목"** 코드 블록으로 별도 출력합니다. `pastor_journal.md`의 스키마와 현재 항목이 실제 제공된 경우에만 기존 값에 병합할 YAML을 작성합니다. 없으면 키·배열 구조를 추정하지 말고 “기존 항목 확인 후 반영할 메모”로 본문 식별 정보와 이번 작업 사실만 건넵니다. 기존 배열 전체를 교체하도록 안내하지 않습니다.
3. PII 정책은 동일하게 적용합니다 — 출력 블록에도 실명을 남기지 않습니다.

## §6. 본문 팩 우선 (Passage-Pack First) — 설교·목양 스킬 공통

작업 범위를 먼저 구분한다. **원문 기록만** 요청하면 전문 요청·브리핑·질문 없이 기록한다. **제공 구절 범위의 동행/변환**은 확보된 부분만 사용하고 전체 문맥·장르를 단정하지 않는다. **전체 본문 해석·주해 또는 누락 구절을 전제로 하는 주장**은 필요한 전문 확보 전 그 분석을 대기한다. 발행 변환은 제공된 목회자 원문으로 시작할 수 있으나 새 성경 인용을 만들지 않는다. 아래 조회는 부족한 본문이 작업에 필요할 때만 수행한다.

1. AGENT 모드: `tools/exegete/pastor_adapter.py`가 있으면 먼저 호출하여 `data/scripture/`의 요청 역본을 조회합니다. 호출 예시는 `python3 tools/exegete/pastor_adapter.py "요3:16" --kind passage --edition "개역개정"`입니다. 이번 요청에서 사용자가 지정한 역본을 `--edition`으로 우선 전달하고, 지정하지 않았으면 `core/foundation.md`의 `preferred_bible`을 사용합니다. 이미 제공한 본문은 파일 자동 선택으로 덮어쓰지 않습니다.
2. `passage.status == "ok"`이고 `capabilities.passage.available == true`, `capabilities.passage.complete == true`일 때 그 결과를 본문 팩으로 사용합니다. `partial`, `unavailable`, `invalid_request`, `error`는 성공으로 취급하지 않으며, `warnings`, `missing_verses`, `sources`의 해시·역본·레코드 키를 연구 기록에 남깁니다.
3. **역본 자동 대체 금지:** 요청한 역본이 없을 때 개역개정 → 개역한글 → WEB처럼 조용히 바꾸지 않습니다. 다른 역본은 사용자가 명시적으로 선택했을 때만 조회하고 결과에 실제 역본명과 `edition_id`를 표시합니다.
4. 어댑터가 없거나 본문 팩을 확보하지 못하면 먼저 기존 `data/scripture/`의 책별 슬롯을 직접 확인합니다. 거기에도 요청 역본의 전문이 없으면(또는 CHAT 모드) 전문이 필요한 분석에 한해 사용자에게 **필요 범위의 본문 붙여넣기를 한 번 요청**하고 그 분석만 기다립니다. 부분 동행에서는 범위를 표시하고 계속합니다. 세션 내 동일 본문 재요청은 하지 않습니다. CHAT 모드에서 CLI를 실행했거나 저장했다고 보고하지 않습니다.
5. 🚨 **기억으로부터의 성경 인용 금지:** 확보된 본문 팩이 유일한 인용 원천입니다. 이후 모든 직접 인용·절 번호는 본문 팩과 대조하고, 대조 불가 인용은 "(검증 불가)"를 명시합니다.
6. 확보된 본문과 출처는 연구 기록에 보존합니다. 배포용 본문에 전문을 중복 강제하지 않습니다. 어댑터 JSON은 증거 입력이며 `pastor_journal.md`, `_manifest.md`, `stage`를 직접 쓰지 않습니다.

### §6.1 선택적 원어 증거 조회

1. `sermon-research`와 `sermon_audit`은 본문 조회와 별도로 같은 어댑터를 `--kind original` 또는 `--kind all`로 호출할 수 있습니다. 구약 요청은 히브리어, 신약 요청은 헬라어 결과를 받으며 두 언어의 가용성을 섞지 않습니다.
2. `capabilities.original_text`와 `capabilities.morphology`가 `available: true`일 때만 원문·원시 형태소 태그를 관찰 자료로 옮깁니다. `lexicon`, `louw_nida`, `discourse`, `lxx`는 각 capability가 따로 `available`일 때만 사용합니다.
3. `available`은 관찰 가능한 항목의 존재이며 전문·전체 파싱 검증 완료를 뜻하지 않습니다. `complete`와 `original_language.provenance_complete`를 따로 확인합니다. 판본·출처·태그 체계 메타가 없으면 판본 검증은 보류합니다. 토큰 총수를 독립 대조하지 못하면 원어 전문 완전성은 미검증으로 기록합니다. 결손·중복·판본 충돌 경고를 보존합니다.
4. 형태소 관찰은 어휘상·상·담화 기능·번역·신학적 해석과 동일하지 않습니다. 어댑터가 제공하지 않는 셀은 "자료 없음/확인 필요"로 두고 기억으로 보완하지 않습니다.
5. 원어 데이터 설치·다운로드는 조회 중 자동 실행하지 않습니다. 설치가 필요하면 `tools/exegete/VENDOR.md`와 `data/_README.md`의 로컬 데이터 절차를 따르고, 사용자 원본과 파생 캐시를 분리합니다.

## §7. 목양 안전 게이트 (Care-Safety Gate) — 목양 스킬 공통

성도의 상황(심방·위로·묵상)을 다루는 스킬은 콘텐츠 생성 **전에** `core/care_safety.md`를 로드하고 위기 신호 스크리닝을 수행합니다. 위기 신호 감지 시 콘텐츠 생성보다 전문 연계 안내가 먼저입니다.

## §8. 입양·원고 등록 (Adopt & Register-Draft) — v2.17

시스템 **밖**에서 태어난 산출물(종이에 쓴 개요, 챗에서 쓴 칼럼, 과거 설교 원고)을 lineage에 소급 편입하는 절차 — 어느 단계든 정문이 됩니다(독립 진행의 양방향 문).

1. **대상·출처 확인:** 무엇이며 언제 만들어졌는지 1회 확인. **내용은 수정하지 않는다** — 입양은 보관이지 개작이 아니다.
2. **passage_id 판정:** §2 규약. 본문 없으면 `topic-{slug}`.
3. **YAML 소급 부여:** `date`(원 작성일 — 모르면 입양일 + `adopted_date_unknown: true`), `skill: adopted`, `stage`(내용에 맞는 값 — 목회자와 확인), `adopted: true`.
4. **버전 번호:** 대상 폴더 스캔 후 다음 `v{NN}`.
5. **Manifest:** `- v{NN} (입양) {설명} ({원 작성일}) · {레포 상대 파일 경로}` — 읽고-병합-쓰기.
6. **Journal:** 선포 여부를 **확인한 후에만** 반영 — 선포됨: `preached_on` 채움 / 미선포: stage만 갱신. 확인 없이 등재하지 않는다. PII 정책 동일 적용.

**register-draft (특수형):** 목회자가 직접 쓴 설교 초안·최종 원고의 등록 — `stage: drafted`(선포된 원고면 `preached`). 이로써 `drafted` 단계가 실체를 갖고, `sermon_audit`·`sermon-retro`·재생산 스킬·주간 세트(심화)가 **실제 원고를 참조**할 수 있게 됩니다. 대필 거절 원칙과 무관합니다 — AI는 원고를 쓰지 않고 보관만 합니다.

## §9. 상류 자동 참조 (Upstream Auto-Reference) — v2.18

lineage 하류 스킬(주해·난제·개요·red-team 등)이 상류 산출물을 매번 "복사해 붙여넣어" 받던 인수인계를 AGENT 모드에서 자동화합니다. 씨앗 거울(`sermon-outline-codraft` 4.5단계)·red-team의 SSOT 로드와 **동형 패턴**의 일반화입니다.

1. **AGENT 모드:** 스킬 실행 시작 시 같은 `outputs/sermons/{passage_id}/` 폴더의 `_manifest.md`를 읽고, 자신의 직전 단계 산출물(해당 skill의 최신 `v{NN}`)을 자동 로드한다. 로드 후 1줄 브리핑: `📎 v{NN} {skill}({date})를 참조합니다.` 목회자가 다른 버전·다른 파일을 지정하면 그것이 우선한다.
2. **씨앗 파일 특례:** `qt-germinate-seed` 산출물을 참조할 때는 `## 접합 블록 (브레인스토밍 입력)` 섹션만 컨텍스트에 올린다 (대화 프로토콜 원문 제외).
3. **폴더에 상류 산출물이 없으면:** 대화에 제공된 원문을 먼저 사용한다. 그것도 없고 요청 수행에 필수일 때만 붙여넣기를 요청한다. 있는 척 진행하거나 기억으로 채우지 않는다.
4. **CHAT 모드:** 이미 제공된 자료는 중략 없이 재사용하며, 수행에 필수인 미제공 자료만 요청한다.
5. **경계:** 자동 참조는 **읽기**만이다. 상류 파일을 수정하지 않으며, 상류의 `stage`를 되돌리지 않는다(§3.6 원리).

## §10. 낭독 시간 가정

리허설·TTS는 **실제로 읽을 본문**의 유니코드 글자수(공백·문장부호 포함, 줄바꿈 제외)를 세고, 기본 가정 **분당 300자**로 나눈다. 이는 제품 내 추정 가정이며 한국어 설교의 실측 평균이나 재생시간 보장이 아니다. 기본 3분 대본은 약 900자를 목표로 삼는다. 제목·YAML·출처·연출 메모는 읽도록 요청한 경우에만 포함한다. 실제 낭독 글자수와 시간이 있으면 그 속도로 보정하고, 쉼·강조에 따른 차이를 제작 메모에 표시한다. 도구로 세지 못했으면 글자수를 실측했다고 말하지 않는다.

## §11. 파생 발행물 최소 점검

칼럼·성도 묵상·블로그·카드 문안·TTS는 출력 전에 원문 의미, 인용/일화 출처, 독자 눈높이, 요청 분량, 문체 우선순위(`pastor_voice.md`)를 점검한다. 원천 밖의 주장·일화·적용을 추가하지 않고 명시한 제외 대목은 문맥으로도 되살리지 않는다. 매체별 점검은 각 스킬에 남긴다. 게시용 본문을 먼저 제공하고 출처·분량 측정·미확인 근거·제작 메모는 별도 기록한다. 초안 저장과 목회자의 의미 확정, 실제 외부 게시 확인은 각각 다르며 §3.6을 따른다. 감사는 선택적 권장이고 모든 결과의 추가 문답 관문이 아니다. 감사 안내는 실제 게시 준비에 필요할 때 결과 뒤 한 번만 두며 결과 앞의 상시 안내나 중복 CTA로 출력하지 않는다. 분량을 센 뒤 인접 문단이 같은 관찰을 말만 바꾸어 반복하는지 확인하고 중복을 덜어낸 후 다시 센다. 원문이 요청 분량을 뒷받침하지 못하면 의미 없는 반복·침묵으로 분량을 충족한 척하지 않고 실제 분량을 표시한 초안과 필요한 원문 범위를 안내한다.
