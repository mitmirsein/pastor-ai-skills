# 🧪 Routing Eval (라우팅 회귀 평가)

> **harness 위계 도구** — 사역 작업 도구가 아니라 *시스템 품질 보증* 도구입니다. 프롬프트 시스템도 회귀합니다: 측정 없는 22+스킬 라우터는 새 스킬 추가에서 조용히 무너집니다.

## 실행 시점

1. `skills/`에 스킬을 추가·제거·이름 변경했을 때
2. `skills/00_pastor_concierge/SKILL.md`의 라우팅 규칙을 수정했을 때
3. 정기 점검 (분기 1회 권장)

## 평가 절차

1. **격리 로드**: `skills/00_pastor_concierge/SKILL.md`(라우팅 규칙)와 스킬 인벤토리 목록만을 판단 근거로 삼는다. 개별 스킬 본문은 열지 않는다 (Concierge가 실제로 아는 것만으로 평가).
2. **케이스 실행**: `tests/routing_cases.md`의 각 케이스에 대해:
   - `journal:` 접두 케이스는 해당 메모리 상태를 가정하고 판단한다.
   - 발화만 보고 **기대 스킬 열을 가리고** 라우팅을 결정한다 (자기 채점 편향 방지 — 먼저 답하고 나서 대조).
   - `(모호)` 케이스는 "보완 질문 후 X"가 맞으면 정답, 즉답하면 오답.
3. **채점**: 일치 / 불일치 / 부분(보완 질문은 맞았으나 최종 스킬 상이)로 기록.

## 출력 포맷

```markdown
# 🧪 Routing Eval Report ({date})

**정확도: {N}/{총} ({%})** — 기준: 90% 미만이면 Concierge 라우팅 규칙 점검 필요

## 오답 목록
| # | 발화 | 기대 | 실제 판정 | 원인 분석 |
|---|---|---|---|---|

## 권고
- {라우팅 규칙 §N에 키워드 패턴 추가 등 구체 수정안}
```

## 한계 고지 (정직)

- 이 평가는 **같은 모델의 자가 실행**이므로 실제 사용자 발화 분포와 다를 수 있다. 90% 통과가 품질 보증이 아니라 **회귀 감지선**이다.
- 결과 저장: 사용자가 요청할 때만 `outputs/{date}/_eval/routing_eval_{date}.md`.
