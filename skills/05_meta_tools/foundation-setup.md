# 🧭 Foundation Setup (선택형 첫 설정)

이 스킬은 `core/foundation.md`의 값을 목회자에게 맞게 정리합니다. 첫 작업을 시작하기 위해 전체 프로필을 먼저 채우지 않습니다. 작업에 영향을 주는 값만 묻고, 나머지는 `미확정` 상태로 둡니다.

## 1. 현재 상태 확인

진입할 때 `core/foundation.md`를 읽고 YAML의 `confirmed_fields`를 확인합니다.

- `confirmed_fields`에 들어 있는 키만 사용자가 확정한 값으로 취급합니다.
- 목록이 없거나 비어 있으면, `church_name` 또는 `pastor_name`에 `OOO`가 있는지와 관계없이 교단·출석 인원·소재지·신학 지향·톤을 **템플릿 예시 또는 미확정**으로 표시합니다. 샘플 교단과 `attendance_avg: 100`을 실제 정보로 확정하지 않습니다.
- `preferred_bible`은 별도 확정이 없으면 개역개정(KRV)을 기본값으로 사용할 수 있지만, 사용자가 선택했다고 보고하지 않습니다.
- 현재 작업이 미확정 값을 필요로 하지 않으면 설정 마법사를 열지 말고 작업을 계속합니다.

현재 값을 보여 줄 때는 다음처럼 상태를 구분합니다.

```text
교단: 미확정(템플릿 값이 있더라도 실제 교단으로 간주하지 않음)
평균 출석: 미확정
톤: 미확정
```

## 2. 필요한 항목만 묻기

현재 작업 또는 사용자가 지정한 항목만 한 번에 하나씩 묻습니다.

| 키 | 필요한 때 | 질문 예시 |
|---|---|---|
| `preferred_bible` | 성경 인용 역본을 사용자가 정해야 할 때 | “이번 작업에 사용할 역본을 정할까요? 기본은 개역개정입니다.” |
| `denomination` | 절기 강조나 교단별 맥락이 결과를 바꿀 때 | “교단을 어떻게 표기할까요? 모르면 미확정으로 둘 수 있습니다.” |
| `theological_orientation` | 신학적 정렬이 결과를 바꿀 때 | “신학적 지향을 이번 결과에 반영할까요?” |
| `tone_preference` | 발행물·메시지 문체를 맞춰야 할 때 | “이번 결과의 기본 어조를 정해 주실까요?” |
| `qt_source_path` | 외부 큐티 폴더를 스캔할 때 | “읽기 전용으로 살필 큐티 폴더 경로가 있나요?” |
| `church_name`, `pastor_name` | 결과 표기나 저장 메타에 실제 이름이 꼭 필요할 때 | “결과에 표시할 교회명/성함을 알려 주실까요?” |
| `attendance_avg`, `location` | 사용자가 요청하거나 현재 산출에 실제로 필요할 때 | “이 작업에 필요한 범위에서 평균 출석/지역을 정할까요?” |

질문을 시작하기 전에 필요한 키 목록과 이유를 한 줄로 알립니다. 사용자가 `전체 설정`을 명시한 경우에만 전체 필드를 순서대로 묻습니다.

## 3. 중단·나중에·없음

- `나중에`, `건너뛰기`: 해당 키는 건드리지 않고 다음 필요한 키로 갑니다. 현재 작업에 필수였으면 미확정으로 표시한 뒤 가능한 범위에서 작업합니다.
- `중단`, `그만`, `여기까지`: 설정과 현재 작업을 멈추며 파일을 쓰지 않습니다.
- `없음`: 빈 값이 유효한 `qt_source_path` 같은 항목에서만 사용자의 명시적 빈 값으로 기록할 수 있습니다. 다른 키는 미확정으로 남깁니다.
- `앞의 선택 취소`: 아직 저장하지 않은 해당 선택만 취소합니다. 기존 파일의 확정값을 지우지 않습니다. 이미 저장한 값의 변경은 사용자가 명시한 새 값 또는 삭제 요청 범위만 반영합니다.
- 이미 대화에서 받은 값은 재개할 때 다시 묻지 않습니다.

## 4. 미리보기와 저장

1. 이번 대화에서 사용자가 확정한 키와 값을 미리 보여 줍니다.
2. 사용자가 “이 값으로 저장/설정해 줘”라고 이미 요청했다면 그 요청을 확인으로 사용하고 재질문하지 않습니다. 제안된 값만 있고 저장 의사가 없을 때만 한 번 확인합니다. 저장이 확인되면 `core/foundation.md`의 YAML 값 중 해당 키만 바꿉니다. 사용자가 건드리지 않은 기존 값과 가드레일 본문은 보존합니다.
3. YAML에 `confirmed_fields`가 있으면 새로 확정한 키를 병합하고, 없으면 목록을 만들어 이번에 확정한 키만 기록합니다. 값이 비워진 키는 사용자가 명시적으로 비운 경우에만 목록에 넣습니다.
4. 저장 전에 중단하면 어떤 부분도 쓰지 않습니다. 저장 후 `마지막 업데이트` 날짜만 현재 날짜로 갱신합니다.
5. 자동 백업을 만들었다고 말하지 않습니다. 실제 경로와 저장 여부만 보고합니다.

미리보기 예시:

```yaml
---
church_name: "[기존 값 유지 또는 이번에 확정한 값]"
denomination: "[이번에 확정한 값]"
tone_preference: "[이번에 확정한 값]"
confirmed_fields:
  - denomination
  - tone_preference
---
```

## 5. Journal·회중 페르소나

이 스킬은 기본적으로 `pastor_journal.md`나 `congregation_personas.md`를 묻거나 수정하지 않습니다. 사용자가 별도로 등록을 요청했을 때 해당 스킬과 절차로 연결합니다. 성도 정보는 직분+이니셜만 사용합니다.

## 6. 출력 규격

- 인터뷰는 정중하고 짧게, 한 번에 한 질문만 합니다.
- 첫 작업을 막지 않는 설정 질문은 생략합니다.
- 결과에는 `① 이번에 확정한 키 ② 미확정으로 남은 키 ③ 실제 저장 경로 또는 저장 불가 안내`만 간단히 적습니다.
- 저장 후 다음 파이프라인을 자동으로 권하지 않습니다. 사용자가 원할 때 가능한 다음 작업 한 가지를 선택 사항으로 안내합니다.

## 저장 계약

- **수정 대상:** 사용자가 확인한 키에 한해 `core/foundation.md`를 직접 수정합니다. `outputs/` 사본은 만들지 않습니다.
- **메모리:** 이 스킬은 설정값만 다루며 `pastor_journal.md`를 갱신하지 않습니다.
- **CHAT/READ_ONLY:** 파일을 쓸 수 없으면 자동 저장을 보고하지 않고, 확정된 YAML 변경 블록과 저장 위치를 제공합니다.
